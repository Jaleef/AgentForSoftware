# 限制与路线图

## 1. 当前已知限制

### 文档

- 仅支持 DOCX；PDF 需先转换，扫描件不做 OCR；
- 页码/行号来自 Word 渲染标记或估算，可能与打印位置有偏差；
- 表格结构依赖 Word 合并单元格和标签文本，异常模板可能漏检；
- 文档版本对比尚未实现。

### 拆分

- 文本需求点、数据库表、文本设计点依赖 LLM 判定；
- LLM 输出存在波动，义务拆分粒度可能变化；
- 子系统分类默认 auto：章节路径优先，其他占比过高时自动用 LLM；也可强制 `heuristic` 或 `llm`；
- 当前没有“义务人工编辑/冻结版本”能力。

### 评价

- 需求→设计已义务级；设计→代码仍是状态级；
- 置信度是覆盖置信度，不是统计概率，尚未校准；
- 启发式回退最多判 partial，但仍是初筛；
- 冲突判定是“任一义务冲突 → mismatch”，粒度较粗；
- 没有金标准回归集和自动质量指标；
- Prompt 注入防护只有提示层约束，没有强隔离。

### 检索

- 默认 BM25F + Legacy + RRF，语义召回需配置 Embedding；
- Dense 依赖外部/本地 embedding 服务；
- Cross-Encoder 每个需求一次调用，成本较高；
- 没有向量索引持久化和 BM25 倒排持久化；
- 没有图召回。

### Agent 架构

- 主 Agent 是确定性编排器，不是 LLM 自主规划；
- 文档整理仍由 `documents` service 作为入口，尚未统一到同一个 MainAgent；
- 暂无 Agent 时间线 UI，`agentRuns` 目前通过 API 读取；
- 断点续跑只做到保留已完成阶段，未实现完整任务恢复。

### 工程化

- 当前是单进程 SQLite，不支持多实例同时写入；
- 评价任务在进程内运行，重启会中断；
- 没有登录、权限、租户隔离；
- API Key 存在本机设置文件/环境变量，文件为明文；
- 没有自动备份、审计日志和 CI；
- 只有 typecheck/build/smoke，没有自动回归测试。

## 2. 非目标

- 不构建/执行代码；
- 不替代测试、安全评估、人工评审；
- 不做多租户 SaaS；
- 不做实时协作；
- 不做完整需求管理/项目管理平台。

## 3. 路线图

### P0：可信度

1. 建立需求-设计金标准；
2. 测 Recall@6、覆盖 F1、状态准确率；
3. 校准置信度，增加“需复核”阈值；
4. 义务人工编辑和版本冻结；
5. 增加覆盖矩阵单元测试。

### P1：能力补齐

1. 设计→代码义务级覆盖；
2. 需求/设计版本 diff；
3. 需求/设计/代码追溯视图；
4. 批量审核、按风险/置信度筛选；
5. 检索缓存和增量评价。

### P2：工程化

1. Postgres/多实例存储；
2. 持久化任务队列、断点续跑；
3. 登录/权限/审计；
4. OpenAPI 契约；
5. CI 与回归测试；
6. 配置项集中管理。

### P3：研究

1. 异构图召回；
2. GNN rerank；
3. 多模态文档；
4. 更强的提示注入防护。
