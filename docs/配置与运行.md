# 配置与运行

## 1. 环境要求

- Node.js ≥ 24
- pnpm ≥ 9
- 本地磁盘可写
- 内置 `node:sqlite`，不需要额外数据库服务
- 可选：OpenAI 兼容 LLM、Embedding、Rerank 服务

## 2. 开发与生产

| 环境 | 启动                         | LLM 配置来源                     | 前端                      |
| ---- | ---------------------------- | -------------------------------- | ------------------------- |
| 开发 | `pnpm dev`                 | 根目录 `.env` 优先，否则设置页 | Vite `5173`             |
| 生产 | `pnpm build && pnpm start` | 设置页，不加载 `.env`          | Express 静态文件 `8787` |

开发模式 `pnpm dev` 会同时启动 API 和 Vite；生产模式只有一个 Node 进程。

## 3. 数据目录

默认：

```text
data/
├── app.db           # SQLite：项目、文档、快照、评价、设置
├── app.db-wal       # WAL 日志（运行时）
├── app.db-shm       # 共享内存索引（运行时）
└── uploads/         # 上传的 DOCX
```

可用 `DATA_DIR` 覆盖：

```bash
DATA_DIR=D:\data\consistency pnpm start
```

注意：

- `data/` 不应提交 Git；
- SQLite 使用 WAL 模式，写入按实体行级更新；
- 备份时备份 `app.db` 和 `uploads/`；运行中备份建议先停止服务，或使用 SQLite backup/`VACUUM INTO`；
- 旧版 `store.json`、`settings.json` 会在首次启动时迁移并改名为 `*.migrated-*`，确认无误后再清理。

## 4. LLM 配置

### 4.1 开发 `.env`

```dotenv
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-chat
LLM_TEMPERATURE=0.1
LLM_MAX_TOKENS=4096
LLM_CONCURRENCY=6
LLM_TIMEOUT_MS=120000
LLM_JSON_MODE=true
LLM_MOCK=false
```

别名：`OPENAI_*`、`DEEPSEEK_*`。

只要 `.env` 中存在任意 `LLM_*`，设置页进入只读“开发环境 · .env”模式。`.env` 只在进程启动时加载，`tsx watch` 不会监听它；修改后必须重启 `pnpm dev`。设置接口会返回 `meta.envFileChanged`，测试接口检测到文件在启动后被修改时会直接提示重启。

进程环境变量优先于 `.env`。如果启动 `pnpm dev` 的终端里已经设置了 `LLM_API_KEY`/`LLM_MODEL` 等变量，`.env` 中同名的值不会生效；`meta.shadowedKeys` 会列出被覆盖的变量名。请先从该终端移除这些变量，再重启服务。

### 4.2 生产设置页

`/settings` 保存到 `data/app.db` 的 `settings` 表。接口返回时 API Key 脱敏；数据库中仍是明文，需限制数据目录访问权限。

### 4.3 连接测试与降级

- 创建评价前会做轻量连通性测试；
- 失败则本次评价回退启发式，并在任务 warnings 标注；
- 单个 batch 失败回退该批，不中断整个任务。

## 5. 可选 Embedding/Rerank

### 5.1 Dense 语义召回

```dotenv
EMBEDDING_MODEL=bge-m3
EMBEDDING_BASE_URL=http://127.0.0.1:8000/v1
EMBEDDING_API_KEY=local-key
EMBEDDING_BATCH_SIZE=32
EMBEDDING_TIMEOUT_MS=60000
```

要求 OpenAI 兼容 `/embeddings`。

### 5.2 Cross-Encoder 重排

```dotenv
RERANK_MODEL=bge-reranker-v2-m3
RERANK_BASE_URL=http://127.0.0.1:8001/v1
RERANK_API_KEY=
RERANK_TIMEOUT_MS=60000
```

要求通用 `/rerank` 接口。默认关闭；每个需求一次调用，适合高精度低吞吐场景。

未配置时检索只使用 BM25F + Legacy + RRF，不影响启动。

## 6. Mock 联调

```bash
pnpm mock:llm
```

Mock 地址：

```text
http://127.0.0.1:8899/v1
```

支持 chat completions、embeddings、rerank 的简化响应。开发 `.env`：

```dotenv
LLM_BASE_URL=http://127.0.0.1:8899/v1
LLM_API_KEY=test
LLM_MODEL=mock-model
```

## 7. 常用命令

```bash
pnpm dev              # 开发
pnpm build            # 构建
pnpm start            # 生产
pnpm typecheck        # 类型检查
pnpm smoke            # 解析示例文档
pnpm retrieval:smoke  # 混合检索 smoke
pnpm agents:smoke     # 主/子 Agent 对比 smoke
pnpm store:smoke      # SQLite 迁移/读写 smoke
pnpm eval:heuristic   # 启发式评价
pnpm mock:llm         # mock 模型
```

`pnpm eval:heuristic` 依赖 `examples/demo-app`；当前工作区若缺少该目录会报错，恢复示例代码库后再运行。

## 8. 性能与并发

文档整理慢的主要原因是**LLM 调用次数**，不是单个请求超时：

- 需求示例约 42–46 次调用：103 个文本点按 8 个/批判定，166 个单元按 6 个/批生成，加 taxonomy；
- 设计示例约 55 次调用：113 个候选按 6 个/批判定，149 个单元按 5 个/批生成，加 taxonomy。

`LLM_CONCURRENCY` 控制批次的并发数。旧版本内部把拆分并发硬限制为 3，设置为 6 也不会生效；当前已放宽到 8。

推荐：

```dotenv
LLM_CONCURRENCY=6
LLM_MAX_TOKENS=4096
LLM_TIMEOUT_MS=120000
LLM_JSON_MODE=true
```

- 先试 `6`；如果出现 429/限流或大量重试，降到 `4–5`；
- `LLM_MAX_TOKENS` 不是速度开关。多数拆分调用固定使用 4096，调大不会减少调用次数，反而可能增加生成时间；
- `LLM_TIMEOUT_MS` 只控制失败等待，不是越快越好；120000 适合 DeepSeek 结构化输出；
- taxonomy 的章节 assignment 已按 40 个/批并行请求，减少串行等待；
- 如需进一步提速，优先增加批次大小或复用上一次解析结果，而不是无限提高并发。

## 9. 部署建议

- 只监听 `127.0.0.1` 或受控内网；
- 反向代理加认证和 TLS，不要直接公网暴露；
- 限制 `data/` 文件权限；
- 定期备份 `data/app.db` 和 `uploads/`；
- 不建议多实例共享同一个 `app.db`；当前只支持单进程写入；
- 生产环境设置 `NODE_ENV=production`，避免加载 `.env`。

## 10. 故障排查

| 现象                        | 检查                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------- |
| 端口占用                    | 5173/8787 是否被旧进程占用                                                             |
| LLM 未配置                  | `/api/health` 的 `llmConfigured`；开发看 `.env`，生产看设置页                    |
| 测试 Key 与 `.env` 不一致 | 看测试响应 `source`/`apiKeyHint`；`meta.envFileChanged=true` 时重启 `pnpm dev` |
| 页面仍显示旧 401            | 旧警告是历史记录；重启后重新「LLM 整理」，成功会清理旧失败警告                         |
| LLM 超时                    | `LLM_TIMEOUT_MS`、网络、网关限流                                                     |
| Embedding 失败              | `EMBEDDING_*`、`/embeddings` 兼容性；失败会自动回退                                |
| Rerank 失败                 | `RERANK_*`、`/rerank` 返回格式；失败会回退 RRF                                     |
| 文档解析异常                | DOCX 是否为 Word 生成、是否有损坏表格                                                  |
| 示例评价失败                | `examples/demo-app`、`文档例子/` 是否存在                                          |
| 数据损坏                    | 检查 `data/app.db` 与 `*.migrated-*` 备份；停止服务后从备份恢复                |
| Node 启动报 node:sqlite     | 升级到 Node ≥ 24；不要用 Node 20                                        |
