# 产品需求与范围

## 1. 产品定位

面向软件质量评审的本地工具，用 DOCX 需求规格说明书、软件设计说明书和代码快照，辅助回答两个问题：

1. 设计是否覆盖需求的全部可核验义务；
2. 代码是否实现设计的接口、输入输出、数据结构和行为。

系统输出**辅助评审材料**，不替代测试、安全评估和人工评审。

## 2. 目标用户

| 用户 | 主要诉求 |
| --- | --- |
| 需求/系统工程师 | 检查需求拆分是否完整、设计是否逐条响应 |
| 架构师/设计人员 | 检查设计单元是否覆盖需求义务、设计是否可追溯到代码 |
| 评审/QA | 快速定位缺失、冲突和部分覆盖项，保留证据与人工结论 |
| 项目负责人 | 查看覆盖率、得分、门禁和问题分布 |

## 3. 核心场景

1. 上传 SRS，自动抽需求点并生成需求单元；
2. 上传 SDD，自动抽设计点并生成设计单元；
3. 登记代码快照；
4. 创建需求→设计或设计→代码评价；
5. 查看逐条关系、义务覆盖、证据和缺口；
6. 人工确认/驳回；
7. 导出报告。

## 4. 产品需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| PRD-01 | 项目管理 | 可创建/查看/删除项目和项目资料 |
| PRD-02 | 需求拆分 | 需求表直接解析；文本章节由 LLM 判定；生成需求单元与义务 |
| PRD-03 | 设计拆分 | 结构化设计表直接解析；数据库表/文本由 LLM 判定；生成设计单元 |
| PRD-04 | 子系统归类 | 根据带编号章节路径归纳少量子系统，不按章节名硬编码类型 |
| PRD-05 | 人工维护 | 需求/设计单元可手工新增、删除、审核；删除同步移除对应点 |
| PRD-06 | 代码快照 | 可登记代码目录，静态抽取文件、符号、路由、数据模型 |
| PRD-07 | 需求→设计评价 | 支持多设计联合覆盖；状态为 satisfied/partial/missing/mismatch |
| PRD-08 | 设计→代码评价 | 支持 implemented/partial/missing/divergent 状态 |
| PRD-09 | 检索 | 义务级候选召回；默认 BM25F + Legacy + RRF，可选 Dense/Rerank |
| PRD-10 | 证据与复核 | 每条关系保存证据、缺口、建议、置信度、方法、人工审核状态 |
| PRD-11 | 报告 | 支持页面报告、Markdown/CSV/JSON 和打印 |
| PRD-12 | 配置 | 开发 `.env`，生产设置页；LLM 可选，失败可降级 |
| PRD-13 | 可运维性 | 本地启动、数据目录可配置、错误可定位、任务可取消 |
| PRD-14 | 安全边界 | 单用户本地使用；不暴露公网；密钥不返回前端 |

## 5. 非目标

- 不做代码构建、执行、动态分析或运行时验证；
- 不评价代码质量、性能、安全性本身；
- 不替代人工评审、测试报告或安全评估；
- 不做多租户、SSO、复杂权限（当前版本）；
- 不做 PDF/扫描件 OCR（当前版本）；
- 不保证 LLM 判定事实正确，必须人工复核。

## 6. 成功指标

| 指标 | 目标 |
| --- | --- |
| 需求表解析可用性 | 示例需求表全部进入规则需求点 |
| 设计表解析可用性 | 结构化设计表保留接口/输入/输出 |
| 评价可解释性 | 每条关系有证据、缺口、建议、方法 |
| 多设计覆盖 | 支持一个需求被多个设计联合覆盖 |
| 可回退性 | 无 LLM、LLM 失败、检索失败均可完成或明确失败 |
| 可复现性 | 相同文档+模型+Prompt 版本可重复得到可比较结果 |

## 7. 约束

- 仅 DOCX；页码行号来自 Word 渲染标记或估算；
- 依赖 LLM 的环节存在模型波动；
- 当前存储为本地 JSON，单用户；
- 设计→代码仍是状态级判断，尚未义务级；
- 示例数字随文档和模型变化，不属于产品不变量。
