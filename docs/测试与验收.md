# 测试与验收

## 1. 当前验证手段

| 命令 | 覆盖内容 | 是否自动断言 |
| --- | --- | --- |
| `pnpm typecheck` | 前后端 TypeScript 类型 | 是 |
| `pnpm build` | 前端构建 + 后端编译 | 是 |
| `pnpm smoke` | 示例 DOCX 解析、代码扫描、统计输出 | 人工观察 |
| `pnpm retrieval:smoke` | BM25F/Dense/RRF 候选输出 | 人工观察 |
| `pnpm agents:smoke` | 新旧评价管线状态对比 + AgentRun | 人工观察 |
| `pnpm store:smoke` | SQLite 迁移、设置读写、重开数据库 | 断言 |
| `pnpm eval:heuristic` | 无 LLM 启发式评价 | 人工观察 |
| `pnpm mock:llm` | 本地 chat/embedding/rerank mock | 联调用 |

当前**没有**单元测试、集成测试和端到端自动断言；这是已知缺口。

## 2. 测试分层

### 2.1 解析器测试

应覆盖：

- DOCX ZIP/XML 读取；
- 标题层级、合并单元格、分页估算；
- 需求表规则点；
- 纯文字叶子章节候选；
- 设计表规则点；
- 数据库表字段；
- 代码符号/路由/模型抽取；
- 异常 DOCX、空文档、TOC、图题。

### 2.2 拆分 Agent 测试

应覆盖：

- 表格规则点置信度 100%；
- 文本点 LLM 判定；
- 子系统分类映射：对象、裸类别数组、仅 assignments 数组、类别有但 assignments 缺失、assignment JSON 截断；
- 手工单元在 LLM 重跑后保留；
- 删除单元同步删除点；
- 无 LLM 回退；
- LLM 批次失败回退。

### 2.3 评价引擎测试

必须覆盖义务覆盖矩阵：

- 单设计覆盖全部义务 → satisfied；
- 两个设计联合覆盖 → satisfied；
- 部分覆盖 → partial；
- 存在冲突 → mismatch；
- 无覆盖 → missing；
- 非法义务 ID / 非法 designCode；
- 同一义务被多个设计覆盖；
- 同一设计覆盖多条需求；
- confidence 聚合；
- coverageRatio 和得分。

### 2.4 检索测试

- BM25F 字段权重；
- 义务级候选并集；
- RRF 融合；
- Dense 关闭时回退；
- Embedding 失败回退；
- Rerank 失败回退；
- Recall@K（需要金标准）。

### 2.5 任务与 API 测试

- 创建评价 → running → completed；
- 取消；
- 服务重启恢复；
- 文件上传/重解析/删除；
- 手工单元 CRUD；
- 关系审核后重新汇总；
- 导出格式。

## 3. 验收标准

### 功能验收

- 需求表全部成为规则需求点；
- 设计表保留接口/输入/输出；
- 需求→设计关系显示义务覆盖；
- 多个设计可以联合覆盖一个需求；
- 无 LLM 时系统仍可启动并明确降级；
- 手工单元在重跑后保留；
- 报告包含证据、缺口、方法和审核状态。

### 质量验收

- `pnpm typecheck` 通过；
- `pnpm build` 通过；
- `pnpm retrieval:smoke` 输出候选和通道；
- 金标准上的 Recall@6、状态准确率、覆盖率误差达到项目阈值（待建立）；
- 无 P0 数据丢失/密钥泄露问题。

## 4. 金标准建议

建立 100–200 条需求-设计关系：

- 人工标注正确设计单元；
- 标注每条义务是否被覆盖；
- 标注状态；
- 标注证据是否成立；
- 记录标注人和分歧。

指标：

```text
检索 Recall@6 / Recall@10
覆盖 Precision / Recall / F1
状态准确率
coverageRatio MAE
置信度校准 ECE
```
