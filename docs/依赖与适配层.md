# 依赖与适配层

本页记录哪些通用能力使用成熟库、适配层在哪里，以及哪些业务逻辑仍然自己维护。

## 1. 库与适配层

| 能力 | 库 | 适配层 | 说明 |
| --- | --- | --- | --- |
| DOCX 解压 | `fflate` | `server/src/parsers/zip.ts` | 保留 `ZipArchive` API，docx.ts 不依赖库 |
| OOXML 解析 | `fast-xml-parser` | `server/src/parsers/xml.ts` | `preserveOrder` 保留段落/表格顺序，转换为 `XmlNode` |
| LLM 调用 | `openai` | `server/src/llm/client.ts` | 保留 `LlmClient` API，处理 JSON 降级、usage、预算、取消 |
| BM25 检索 | `minisearch` | `server/src/evaluation/hybrid.ts` | 字段 boost 对应原 BM25F 权重，RRF/结构重排仍由项目实现 |
| `.env` 解析 | `dotenv` | `server/src/config/env.ts` | 只用 `parse`，保留进程环境变量优先和 shadowedKeys 诊断 |
| 前端请求缓存 | `@tanstack/react-query` | `web/src/hooks.ts` | `useResource` 内部改用 `useQuery` |
| 测试 | `vitest` | `server/src/**/*.test.ts` | 解析/检索回归 |
| 死代码扫描 | `knip` | `knip.json` | 扫描未使用文件/导出 |

## 2. 注释要求

所有第三方库调用集中在适配层，并用 JSDoc 写清：

1. 调用了哪个库的哪个函数；
2. 为什么需要适配层；
3. 输入/输出；
4. 失败、超时、回退；
5. 与业务语义的边界。

示例：`zip.ts` 的 `ZipArchive` 注释说明 `fflate.unzipSync`、DOCX 错误语义；`client.ts` 的 `LlmClient` 注释说明 `chat.completions.create`、JSON mode 降级和 usage 映射。

## 3. 保留自研的部分

- `docx.ts`：合并单元格、标题层级、分页、页码/行号；
- `requirements.ts` / `design.ts`：领域拆分规则；
- `obligations.ts` / `summary.ts`：义务覆盖与评分；
- `code.ts`：多语言静态扫描启发式；
- `store.ts`：SQLite 行级 diff 和事务；
- `text.ts`：领域词典和跨语言别名；
- `ui.tsx` / `styles.css`：界面设计系统。

## 4. 不使用的大件

- 不使用 LangChain/LangGraph：LLM 调用是固定函数管道，引入框架会增加抽象和调试成本；
- 不使用 Prisma/ORM：SQLite 顶层实体 JSON 足够，ORM 会增加迁移和类型复杂度；
- 不使用 FAISS/HNSW：当前设计单元规模较小，内存余弦足够；
- 不使用 Elasticsearch：本地单进程不需要独立检索服务；
- 不使用 tree-sitter 全量替换多语言代码扫描：grammar 和 AST 适配成本过高。

## 5. 升级与回退

- 依赖版本由 lockfile 固定；
- 适配层隔离库 API，升级只改适配层；
- 替换前后用 `pnpm test`、`pnpm smoke`、`pnpm retrieval:smoke` 对比；
- 解析/检索行为不一致时先回退适配层，不直接改业务规则。
